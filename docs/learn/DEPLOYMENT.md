# 다른 기기에서 읽는 학습 사이트

강의 사이트는 게임 서버와 별개인 정적 HTML 사이트다. 개발용 소스 조회 API가 없어도
강의 본문·코드·전체 참고 원문·배포 시점 소스·확인 문제를 읽을 수 있다.
[공개 강의 사이트](https://rein-arxiv.github.io/Tetris-Multiplayer-RL/)에서 접속한다.
`main`의 검수 완료 강의와 코드 레퍼런스를 정적 배포물로 생성한다.
공개 배포 결과는 저장소의 **Learning site** Actions 작업과 `github-pages` 환경에서,
실제 제공 중인 내용 식별값은 사이트의 `site-manifest.json`에서 확인한다.
`PUBLICATION.json`은 배포 방식과 과거 공개 이력을 기록한다.

## 배포물 만들기

저장소 루트에서 자료를 갱신하고 정적 배포물을 만든다.

```bash
python3 scripts/build_learning_library.py
python3 scripts/build_learning_coverage.py
python3 scripts/build_learning_lessons.py
python3 scripts/build_learning_site.py
```

Python과 markdown-it-py 3.0.0이 필요하다. 기존 환경에서 해당 패키지를 사용할 수 없으면
학습 README의 uv 실행 방법을 사용한다. 배포 서버에는 생성된 정적 파일만 필요하며
Python·CMake·SDL·프로젝트 소스 저장소를 따로 설치할 필요가 없다.

출력은 `out/learning-site/releases/<배포 ID>/`와 같은 ID의 ZIP이다.
ID는 입력 자산 내용에서 계산한다. 변경이 없다면 같은 배포 ID와 같은 ZIP 바이트가
나온다. 기존 ID의 디렉터리가 다른 내용으로 수정되어 있으면 덮어쓰지 않고 실패한다.
원고/참고 자료가 낡은 상태에서는 먼저 생성물을 갱신하라는 검사 오류를 낸다.

복사 목록은 HTML·CSS·JS와 포함된 외부 라이브러리의 라이선스로 한정한다.
원고 JSON, 작업 로그, AI 응답, DB, 사용자 답안, 설정·인증 파일을 수집하지 않는다.
`library.js`에는 강의에서 참조하는 프로젝트 소스와 원문이 들어 있다. 사이트를
공개하면 그 자료도 방문자가 읽을 수 있다는 범위를 배포 검토에 포함한다.
검토된 강의의 명시적 코드 레퍼런스는 Part 문장의 파일명 언급과 독립적으로 포함한다.
소스 허용 경로/확장자 필터는 동일하게 적용하며 숨김 경로와 심볼릭 링크 경유는 제외한다.

## 서버에 올릴 때 유지할 조건

- 생성된 디렉터리 안의 파일만 정적 사이트의 문서 루트 또는 선택한 하위 경로에 올린다.
- 링크와 자산은 상대 경로다. 예를 들어 `/courses/tetris/` 아래에도 같은 파일을 놓을 수 있다.
  디렉터리 주소 끝에 `/`를 붙이고 서버가 index.html을 제공하도록 구성한다.
- 차시 주소는 `#lesson-9` 같은 fragment를 사용하므로 차시마다 서버 rewrite가 필요하지 않다.
- 접속 주소는 HTTPS로 제공한다. 실제 서버 제품·인증·도메인 설정은 배포 환경에 맞춘다.
- index.html은 업데이트 때 다시 확인하도록 캐시 정책을 둔다. 생성된 자산 URL에는 내용
  해시가 들어 있어 새 index를 읽으면 해당 버전의 자산을 요청한다.
- 업데이트는 완성된 배포 디렉터리를 먼저 올린 뒤 서비스 대상을 전환한다. 파일을 하나씩
  운영 경로에 덮어쓰면 서로 다른 버전의 강의/코드가 잠시 섞일 수 있다.
- 과거 배포 디렉터리를 보관하면 사이트 파일을 이전 버전으로 되돌릴 수 있다.
  사용자의 브라우저 답안까지 되돌리는 작업은 아니다.

개발용 scripts/serve_learning.py는 현재 작업 폴더를 읽는 루프백 도구다.
이 도구를 외부로 열어 배포하는 방식으로 바꾸지 않는다. 정적 배포본은 해당 API에
접속하지 않고 “배포본 코드”와 배포 ID를 표시한다. 게임 소스가 바뀌면 배포물을
다시 만들어 올려야 그 배포본의 레퍼런스도 갱신된다. 강의 기준 스니펫은 별도다.

## 여러 기기에서의 학습 기록

현재 답안·완료 표시는 접속한 브라우저에 저장되며 서버 자동 동기화는 없다.
동일 기기라도 주소의 프로토콜·호스트·포트가 바뀌면 별도의 저장 공간이 된다.
페이지 배포만으로 예전 로컬 주소의 답안이 새 서버에 자동 이동하지 않는다.

사용자 요청으로 파일 내보내기/가져오기 기능은 삭제했다. 객관식 선택·확인 상태는
현재 브라우저에 보존되며, 필요한 답안은 복사 기능으로 따로 보관한다. 새 차시를 추가할 때 기존 문제 ID를
재사용하거나 재번호화하지 않아 저장된 답안의 대응을 보존한다.

## 검증 범위

내보내기 전 자료 최신성 검사, 고정 복사 목록과 내용 해시, 같은 입력의 재생성 결과를
검사한다. 로컬의 중첩 경로에서 배포본을 열어 차시 이동·소스 스냅샷·반응형 화면을
확인한다. 이 검사가 실제 외부 서버의 TLS·인증·연결성·다른 기기의 저장 정책까지
확인한 것은 아니다. 실제 배포 환경에서 별도 확인한다.

## 이 저장소의 GitHub Pages 경로

`Rein-ArXiv/Tetris-Multiplayer-RL`의 개발 소스와 강의 원고는 `main`에서 관리한다.
Pages Source는 **GitHub Actions**이며 `.github/workflows/learning-pages.yml`이
자료 갱신·Markdown/원문 발췌·객관식 검사를 통과한 정적 묶음을 배포한다.
공개본의 코드 레퍼런스는 배포 시점 스냅샷이다. 로컬 수정만으로는 공개본이 바뀌지 않는다.

- 공개 주소: [Tetris 동행 강의](https://rein-arxiv.github.io/Tetris-Multiplayer-RL/)
- 집필·제품 코드 기준: `main`
- 배포 입력: 정적 내보내기의 허용 목록에 포함된 파일
- 과거 `gh-pages`: 이전 정적 배포 이력으로 보존하며 현재 소스에 병합하지 않는다.

### 공개본 갱신

1. 집필·코드·Part 문서 검수를 마치고 자료 생성물을 갱신한다.
2. `python3 scripts/check_learning_site.py`로 허용 목록·해시·재현성을 검사한다.
3. 검수된 변경을 큰 단원 경계에서 `main`에 커밋·푸시한다.
4. **Learning site**의 build 성공 뒤 deploy 성공을 확인한다. PR에서는 deploy를 실행하지 않는다.
5. 공개 HTTPS의 `site-manifest.json`과 파일 해시를 배포물에 대조한다.
   실패하면 해당 Actions 로그에서 원인을 확인한다. 저장소 커밋과 공개 완료는 구분한다.

동일 main을 다시 배포할 때는 Actions의 **Learning site → Run workflow**를 사용할 수 있다.
빌드는 외부 AI 모델·API 키 없이 저장소 자료만 사용한다. 공개 사이트에는 게임 서버나
개발용 임의 파일 읽기 API를 올리지 않는다. 답안은 각 브라우저에 저장되며 기기 간
자동 동기화되지 않는다.

첫 공개는 별도 `gh-pages` 브랜치 방식이었다. 현재 방식은 main에서 생성한 Actions
산출물을 배포하므로 배포 브랜치의 HTML로 main 소스를 교체할 필요가 없다.
설정 근거: [GitHub Pages API](https://docs.github.com/en/rest/pages/pages#update-information-about-a-github-pages-site),
[사용자 정의 워크플로](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).


## 필요한 자료만 불러오기

초기 페이지는 강의 묶음과 탐색·저장 코드를 읽는다. `library.js`는 원문·소스 뷰어를
처음 열 때, Mermaid는 선택한 강의나 원문에 다이어그램이 있을 때 `assets.js`가 읽는다.
강의 지도에는 작은 편성 정보만 사용하므로 뷰어를 열기 전에 전체 소스 스냅샷을 읽지 않는다.
같은 자원의 동시 요청은 한 Promise를 공유하며 실패한 요청은 다음 열기에서 재시도한다.
로딩 중 뷰어를 닫거나 다른 자료를 선택하면 이전 요청이 화면을 되돌리지 않는다.

정적 내보내기는 지연 자원도 ZIP에 포함한다. `site-config.js`의 자산 해시로
동적 script URL도 버전을 지정하므로 서로 다른 배포의 코드가 캐시에 섞이지 않게 한다.
모든 경로는 진입 파일 기준 상대 경로이며 하위 디렉터리와 file URL을 지원한다.
배포 시 파일 일부만 복사하지 말고 생성된 묶음을 함께 옮긴다.

현재 강의 본문은 `lessons.js`에 함께 들어 있다. 지연 로딩 적용을 차시별 네트워크
분할과 혼동하지 않는다. 초기 무게는 진입 HTML의 script 목록과 실제 파일 크기를
다시 측정한다. gzip 크기는 서버의 실제 압축 응답을 확인하기 전까지 추정값으로 기록한다.
