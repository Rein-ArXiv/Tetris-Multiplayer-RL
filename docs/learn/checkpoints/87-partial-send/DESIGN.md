# 87 구현 경계

한 번의 OS 호출은 SendAttempt, 전체 작업은 SendReport로 표현한다.
accepted는 로컬에서 수락된 접두사 길이이며 상대 처리 완료나 응답을 뜻하지 않는다.
0 <= accepted <= size를 유지하고 실제 진행량만 더한다. 오류·마감·취소 뒤에도
그 길이를 보존한다. 외부로 이미 수락된 바이트를 롤백하지 않는다.

send_until은 버퍼를 동기적으로 차용하고 송신·시계·대기·취소 콜백을 주입받는다.
빈 요청은 콜백 없이 완료하고 null을 허용한다. 양수 길이의 null은 호출 오류다.
진행 결과의 0/초과 count와 알려지지 않은 상태는 invalid_result로 거절한다.
전체 deadline은 고정하며 작은 진행에도 갱신하지 않는다. WouldBlock 대기 전에도
시계를 다시 읽는다. 마지막 시도가 모두 수락하면 완료를 우선한다.
취소와 시간 검사는 협력적이다. 콜백의 신속한 반환·단조 시계·유효 저장소가 전제이며
OS 스케줄링에 대한 엄격한 반환 시각 보장은 없다.

try_send는 논블로킹 OS send를 한 번 호출한다. POSIX EINTR는 상위에서 시간과
취소를 재검사하게 전달하고, Winsock WSAEINTR는 오류로 전달한다.
반환 0은 합성 오류이며 과거 오류 값을 읽지 않는다. 길이는 축소 전 제한한다.
set_nonblocking은 POSIX의 다른 상태 플래그를 보존하며 실패를 호출자에게 알린다.
send_bounded 자체는 모드를 바꾸지 않는다. atomic_bool은 중단 요청만 전달하므로
relaxed 읽기를 사용하며 다른 데이터 공개의 동기화 수단으로 사용하지 않는다.

serialization_probe만 새 송신 경로를 사용한다. 실패 시 전체 프레임을 재송신하지
않고 연결을 정리한다. 송신 예산은 연결 수립이나 응답 대기까지 포함하지 않는다.
현재 엔진 native tcp_send_all의 bool 계약과 WSS의 비동기 큐 수락 계약은 기준과
구별한다. 이벤트 기반 보류 송신 큐와 연결 재시작 상태는 이번 구현에 포함하지 않는다.
