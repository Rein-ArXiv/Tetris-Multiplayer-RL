# 85 구현 경계

ByteBuffer의 append 계약은 유지하고 consume_front를 추가한다.
초과 소비는 변경 없이 거절하고, 성공 시 남은 꼬리를 앞으로 이동한다.
FrameParser는 고정64바이트와 실패 상태를 소유한다. append 실패는 고정된
파서 오류로 승격한다. next는 need_more/frame/error를 구분한다.
LEN0/>33은 헤더만으로 거절한다. 출력 인자는 frame 성공에만 갱신된다.
프레임 최대35바이트, 완성분 소비 후 꼬리 최대34, read≤16이므로 사용량≤50.
다음 read 전에 반드시 need_more까지 추출해야 이 증명이 성립한다.

프레임 payload를 소유한 값으로 복사한 뒤 버퍼를 소비한다.
배열 전체·구조체 객체 표현을 wire로 보내지 않는다.
종류와 의미 검증은 호출자 책임이다. 서버는 요청1, 클라이언트는 응답2만 허용한다.
세 응답을 검증한 클라이언트가 송신 종료하고 서버 EOF·반대 방향 EOF를 확인한다.
EOF+비어있지 않은 꼬리는 절단이다. 필요한 응답 수는 추가 애플리케이션 조건이다.

누적 게임·렌더러·오디오·기존 소켓 진단 파일은 유지한다.
인증·타임아웃·동시 연결·게임 메시지 통합은 포함하지 않는다.
한 프레임 메모리 상한이 총 요청 수나 대기 시간을 제한하지는 않는다.
현재 엔진의 체크섬·상한·LEN0 처리와 구분해 비교한다.
