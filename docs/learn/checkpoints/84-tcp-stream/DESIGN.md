# 84 구현 경계

기존 게임·한 바이트 Socket API는 유지하고 별도 StreamResult API를 추가한다.
send_some/receive_some은 양수 progress·EOF·error를 구분한다.
유효한 블로킹 소켓·요청 크기만큼 살아 있는 버퍼가 전제다. 길이0은 거절한다.
Winsock int 인자 범위에 맞춰 INT_MAX를 먼저 적용하고 변환한다.
POSIX EINTR만 내부 재시도하고 Winsock 취소는 오류로 보고하며 진행량은 상위의 포인터/길이 갱신에 사용한다.

ByteBuffer<64>는 고정 누적 공간이다. 크기/용량을 구분하고 초과 추가 시 내용을 보존한다.
실패 시 상태 보존은 스레드 원자성과 무관하다. 단일 스레드에서만 사용한다.
shutdown_send는 송신만 종료하고 응답 수신 방향은 남긴다. Socket 소유권은 유지한다.
진단은 요청 EOF 뒤 누적 내용을 echo하며 양쪽이 EOF만 기다리는 순환을 피한다.

실험의 비교 대상은 누적 내용·순서·상한이다. 실제 recv 분할 모양은 고정하지 않는다.
전체32분할 속성 검사는 누적 알고리즘을, 실제 프로세스 검사는 OS API 연결을 확인한다.
반복 메시지 프레이밍·재접속·비동기 큐·타임아웃은 이 작은 EOF 기반 교환에 포함하지 않는다.
