# 소유권과 경계

- MemoryResults가 경기 값과 mutex를 소유하고 HTTP 핸들러는 이를 빌린다.
- 조회/내용 비교/새 행 반영은 한 잠금 구간이다. 기존 행 재확인은 용량 검사보다 먼저 한다.
- 조회는 값의 복사본을 반환한다. 호출자에게 내부 주소나 잠금 수명을 넘기지 않는다.
- HTTP는1024바이트 본문, wire는 평평하고 중복 키 없는 정수 객체를 요구한다.
- study/v1 형식은 정확히 정해진 필드 수를 사용한다. root service wire와 비호환이다.
- HTTP 요청 스레드2·대기열8, 저장행64의 실습 정책이다. 전체 RSS/요청속도를 보장하지 않는다.
- HTTP 서버보다 저장소를 먼저 구성한다. 사용하는 listen 정상 종료는 요청 작업 정리 뒤 반환한다.
- 호출자에는 저장소 구현이 없고 JSON/HTTP 송신 어댑터만 있다. 공유 헤더는 공유 메모리가 아니다.
- HttpSender는 한 번 요청하며 제출 객체의 시도 예산을 중첩하지 않는다. 미확인은 부재 증명이 아니다.
- meta_submit의 값 초기화한 입력과 고정 시드77은 로컬 신뢰된 종료 규칙 실습이다.
- 서버는 숫자loopback으로 고정하고 인증/계정/BP를 구현하지 않는다. 외부 공개에 사용하지 않는다.
- 메모리 저장소는 서비스 재시작에 보존되지 않는다. 현재 SQLite 서비스의 영속성은 별도로 비교한다.
- 기본 OS 종료 신호는 graceful drain 구현이 아니다. 프로세스 재시작 검사는 전원 손실 검사가 아니다.
-108 누적 파일은 README/DESIGN/CMake 외 바꾸지 않는다.
