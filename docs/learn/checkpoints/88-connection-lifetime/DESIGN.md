# 88 구현 경계

Connection은 Socket·FrameParser·send_closed·peer_eof를 소유한다.
active는 핸들 소유 여부이며 상대 응답 가능성이나 게임 준비 상태를 뜻하지 않는다.
양방향 통신이 끝나도 핸들은 close 전까지 소유한다. 이미 active이면 start는 busy로
상태를 보존한다. 실패한 연결 후보는 공개하지 않으며 새 연결에는 새 파서를 쓴다.

finish_sending은 한 번 성공한 shutdown을 기억하고 이후 호출은 로컬 성공으로 처리한다.
EOF는 수신 방향만 닫힌 상태다. 상대 EOF 뒤에도 우리 송신은 가능하며 EOF가 완전한
프레임 경계에 있을 때만 캐시한다. 잘린 프레임·파서 오류·수신 오류는 연결을 정리한다.
next_frame은 파서를 먼저 배출한 뒤 최대 16바이트 읽는다. frame 외 결과는 out을 보존한다.
프레임 단위 성공을 애플리케이션 요청 성공으로 해석하지 않고 호출자가 TYPE·내용·개수를 검사한다.

send_frame은 임시 인코딩 저장소를 호출 종료까지 소유한다. 잘못된 호출은 연결을 유지하고,
모드 변경 실패·송신 미완료·복귀 모드 실패는 연결을 닫는다. 이미 수락된 양은 보고에 남긴다.
close는 핸들 해제·파서/방향 상태 초기화를 반복 가능하게 묶는다. 실패 후 재연결은 명시적이다.
종료 후 동일 요청의 자동 재실행이나 중복 처리 방지는 구현하지 않는다.

모든 메서드는 직렬 호출을 전제로 한다. 진행 중인 블로킹 메서드와 close를 경합시키지 않는다.
단순한 값 소유 모델을 설명하는 기준이며, 실제 Session의 워커 종료 요청·join·공유 핸들
마지막 참조 해제는 현재 소스와 비교한다. OS 핸들의 숫자는 연결 식별자가 아니다.
