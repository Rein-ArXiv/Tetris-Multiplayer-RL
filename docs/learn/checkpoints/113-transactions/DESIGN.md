# 보상 저장의 계약

- v3는 wallets와 match_rewards를 추가한다. 구 경기마다 양쪽0/policy0을 기록하고 지갑0에서 출발한다. 소급 지급 없음.
- 새 경기의 policy1: 승자10, 패자3, draw양쪽0. 실제 서비스 밸런스와 별개다.
- put은 mutex와 BEGIN IMMEDIATE 안에서 기존 키를 확인하고 경기·A/B 잔액·A/B 내역을 커밋한다.
- credit는 private이며 put의 쓰기 트랜잭션/연결 mutex를 전제로 한다. DONE과 변경1행을 함께 검사한다.
- 안전한 덧셈은 상한-before를 먼저 비교한다. 한쪽 실패 시 전체 rollback, 영수증0/storage_error.
- 지급량은 당시 내역을 읽는다. 현재 잔액과 다르며 여러 balance 호출이 같은 읽기 snapshot을 의미하지 않는다.
- 구/신 플레이어 모두 기본 소유와 지갑을 함께 만든다. 시작 검사는 빠진 지갑/지급쌍을 거절한다.
- HTTP 형식은 기존 receipt 그대로다. 신뢰된 경기 판정이나 계정 인증 구현으로 확대하지 않는다.
- 후크/CLI 대기는 로컬 실패 실험용. 커밋 후 응답 유실은 같은키/내용으로 확인하며 재지급하지 않는다.
- 별도 연결은 미커밋 반쪽 상태를 읽지 않는다. BEGIN/COMMIT은 잠금/저장 오류로 실패할 수 있다.
