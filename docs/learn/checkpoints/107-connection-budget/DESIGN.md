# 자원 예산과 실패 보존

- Limits의 단위는 동시 개수와 선언된 예약 바이트다. 시간당 요청 빈도를 세지 않는다.
- 공유 State의 mutex 안에서 상한 검사와 모든 증가를 확정한다. 거절은 상태를 보존한다.
- 키별 표는 MaxKeys로 고정되고 탐색은 O(MaxKeys)다. 키0도 유효하다.
- State만 생성 시 할당한다. 성공 입장 경로는 공유 참조를 복사하고 고정 표를 갱신한다.
- 이동 전용 Lease 하나가 세션 한 개와 선택적으로 진행 중인 핸드셰이크를 소유한다.
- 단계 종료는 핸드셰이크만 한 번 반납한다. reset은 남은 단계·세션·바이트를 반납한다.
- 바이트 합을 계산하기 전에 n <= limit - used로 범위를 확인한다.
- 마지막 State 참조를 가진 reset도 잠금을 먼저 해제하고 State를 파괴한다.
- 같은 Lease의 접근은 호출자가 직렬화한다. 서로 다른 Lease의 공유 카운터 접근은 mutex로 보호한다.
- Budget 자체의 동시 사용자를 끝낸 뒤 파괴한다. 이미 발급한 Lease는 State 수명을 유지한다.
- stop_accepting은 새 입장만 막으며 실행 중인 작업을 취소하거나 완료를 기다리지 않는다.
- probe의 Peer는 lease를 먼저 선언하여 그 Peer의 parser/socket이 lease보다 먼저 파괴된다.
- 표의 예약량은 요청한 저장 범위만 센다. 이동 후 남은 인라인 버퍼나 전체 RSS를 뜻하지 않는다.
- 시간 초과는 별도 상태 관측이다. 소유자가 그 결과에 따라 처리 흐름과 예약을 정리한다.
