# 89 구현 경계

버전 1은 협상 형식, 규칙 ID 1은 이 기준 시뮬레이션의 약속이다.
HELLO payload6 = u16version/u32rules. OFFER와ACK payload20 = 같은헤더/u64seed/
u32countdown/u8inputdelay/u8receiverrole. 초기 직결 협상에서 receiverrole은2(Peer)다.
Config는 공통 값만 소유한다. 호스트의 로컬 역할1을 상대에 그대로 배정하지 않는다.
카운트다운<=600, 입력지연<=30은 학습 정책이며 wire 자료형의 표현 범위와 별개다.
실제 게임은 같은 운영 상한을 사용하도록 바뀐 것이 아니다.

코덱은 정확한 크기·타입·버전·규칙·역할·운영 범위를 검사한 뒤 출력에 반영한다.
호스트는 제안 전체와 ACK의 모든 공통 값이 같은지 확인한다. proposed와 agreed가
같은 객체여도 후보 복사 후 마지막에 반영한다. 잘못된 로컬 제안은 연결과 출력을 보존한다.
전송/수신/프로토콜 실패는 연결을 정리하고 agreed를 보존한다.

negotiate_host/peer는 새 연결에서 한 번 실행하는 순차 상태 절차다. rematch 상태 기계가
아니며 호출자가 성공 이후 메시지 단계를 관리한다. 실패 단계에서 틀린 메시지는 거절하고,
성공 뒤 남은 프레임은 Connection의 파서에 남긴다. EOF는 성공 조건이 아니다.
Peer 성공은 ACK의 로컬 수락, Host 성공은 ACK 검증 완료다. 양쪽 완료 시각이나 상호
관찰의 무한 확인을 보장하지 않는다. 공통 카운트다운은 벽시계 동기화가 아니다.

Connection::adopt는 독점 소유의 연결된 블로킹 소켓을 받는다. busy/invalid 실패는
호출자의 Socket을 보존하며 성공에만 이동한다. 이 전제는 원시핸들 숫자로 증명하지 않는다.
기존 게임·렌더러·오디오와 88차시 진단은 유지한다. seed_probe만 기존 Round를 시드로
생성해 초기 상태 해시를 관찰한다. 실제 네트워크 입력·카운트다운 실행은 아직 연결하지 않는다.
