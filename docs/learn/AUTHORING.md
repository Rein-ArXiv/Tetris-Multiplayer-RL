# 장기 학습 강의의 집필 계약

이 파일은 집필·검토 기준이다. 학습자는 HTML 화면에서 강의를 읽는다.
기존 VeLog Part 0~18 전체를 재료로 삼되, 원문을 순서대로 HTML로 변환한 것은
완성 강의로 인정하지 않는다. 강의 수의 상한을 정해 CS 설명을 압축하지 않는다.

## 서로 다른 세 가지 자료

1. **강의 본문과 기준 스니펫:** 별도로 집필한 안정적인 학습 코드. 핵심 아키텍처와
   구현 과정에서 필요한 세부를 생략하지 않는다. 콘텐츠 개수나 내부 보조 함수 변경에
   맞춰 자동 갱신하지 않는다. 변경하면 강의 버전과 이유를 기록한다.
2. **현재 코드 레퍼런스:** 학습 서버가 현재 작업 폴더에서 읽는다. 파일·심볼을 기준으로
   연결하고 줄 번호는 탐색 보조로만 쓴다. 정적 환경에서는 스냅샷임을 표시한다.
3. **기존 상세 원문:** 전체 맥락, 과거 버그, 비교·참고를 확인하는 자료다.
   코드 블록의 현재 발췌·중간 체크포인트·예시 구분을 보존한다.

1과 2의 차이는 오류 자체가 아니다. 비교 기준은 책임·의존 방향·상태 소유권·입출력
계약이다. 블록/캐릭터 수, UI 수치, 파일 안의 함수 순서, 보조 함수 추출 같은 세부와
아키텍처 계약 변경을 구분한다. 자동 해시 검사는 자료의 변경을 찾을 뿐,
아키텍처가 유지되는지 의미적으로 증명하지 못한다.

## 한 차시의 필수 구성

- 시작 전 짧은 복습: 직전 구현 상태·핵심 개념 2~3개와 이번 구현으로 잇는 한 문단. 정답 목록을 반복하지 않는다.
- 직전 산출물과 이번 차시에서 추가할 작은 기능.
- 기본 CS 정의와 작은 수치/상태 예. C++를 안다고 CS 전반을 안다고 가정하지 않는다.
- 생각 실험 → 최소 구현 → 실패 사례 → 필요한 보강 → 대안과 선택 이유.
- 필요한 파일·빌드 변경·실행 명령·기대 결과. 완성 프로젝트의 대형 소스를 복사해서
  돌아간다는 사실만으로 구현 과정을 대신하지 않는다.
- 강의 기준 스니펫 바로 옆의 현재 코드 보기 버튼. 필요한 함수나 선언으로 이동한다.
- **유지되는 핵심 / 달라질 수 있는 세부 / 이 단계에서는 생략한 것**의 설명.
- 그 차시까지 배운 내용으로 풀 수 있는 3~5문제. 개념·결과 예측·오류 원인·작은 수정
  중 적절한 유형을 섞은 4지선다로 만든다. 하나를 선택하고 확인을 누르면 그 문제 아래에
  정답과 해설을 제공한다. 선택 변경 시 이전 확인 결과를 숨겨 다시 풀 수 있게 한다.

새 개념이 겹쳐 설명이 어려워지면 차시를 나눈다. CS 설명은 용어 나열이 아니라
구체적인 실행 흐름과 연결한다. 본문은 현재 구현 대상과 다음 변화에 집중한다.
“2차시에서”, “3차시의”처럼 번호를 반복해서 독자를 이전 수업으로 되돌리지 않는다.
“앞서/기존/이전”으로 일괄 치환하지도 않는다. 예를 들어 “main은 플랫폼 함수만
호출하지만 빌드 설정은 아직 한 타깃에 모여 있습니다”처럼 상태 자체를 설명한다.
번호는 선수 지식·체크포인트 식별·문제 풀이·실제로 필요한 복습 링크에 사용한다.
복습 링크는 본문 이해에 필요한 경우에만 두며 마지막 문제도 해당 차시에서 바로 해설한다.

## 오개념을 줄이는 설명과 검수

사용자는 별도 지적이 없어도 교육학적·프로그래밍적으로 더 나은 설계와 표현을
적극 적용하도록 요청했다. 다음 기준을 본문과 코드 검수에 함께 사용한다.

- 새 용어는 등장한 자리에서 역할과 작은 사례로 정의한다. 핸들/주소/소유자,
  큐/동기 호출/콜백, API/ABI, 사건/상태처럼 혼동하기 쉬운 개념을 구별한다.
- 주장에는 적용 범위를 붙인다. 예제에서 관찰한 결과, API의 계약, 현재 코드의 정책,
  OS별 미검증 사항을 섞지 않는다. “항상”, “자동”, “안전”, “동일”은 전제가 있을 때만 쓴다.
- 코드 앞에서는 해결할 질문과 예상 흐름을 제시하고, 코드 뒤에서는 실패 사례와
  확인 방법을 연결한다. 전체 파일은 참고할 수 있게 제공하되 핵심 설명을 대체하지 않는다.
- 학습 목표는 만들 산출물과 설명·예측·오류 진단할 수 있는 행동을 연결한다.
  읽음/완료 체크를 이해도 측정으로 표현하지 않는다. 확인 문제는 단순 용어 재진술에
  치우치지 않고 새로운 입력·실패 상황에 적용하게 한다.
- 기술적 세부를 줄여 가독성을 확보하지 않는다. 새로운 전제가 너무 많으면 강의를
  나누거나 짧은 예제로 격리한다. 실제 코드의 전체 기능을 한 번에 이해하라고 요구하지 않는다.
- 모델 검토는 후보 의견이다. 원문·현재 코드·공식 계약과 대조하고 필요한 검사로
  확인한 뒤 반영한다. 표현 개선 때문에 원래의 제한 조건이나 반례를 삭제하지 않는다.

## 집필 기록과 학습 본문의 구분

학습 본문과 차시 머리말에는 집필자의 작업 보고를 넣지 않는다. “집필 환경에서 통과”,
“Windows를 검증하지 못함”, “수정 전후 검사를 수행함” 등의 내용은 review/validation
메타데이터와 REVIEW_LOG.md·PROGRESS.md에만 기록한다. 검수 정보는 화면에 출력하지 않는다.

본문은 배우는 사람이 만들 것, 이유, 실행 방법, 예상 결과와 오류를 다룬다. 테스트가
학습 내용이면 어떤 입력을 주고 무엇을 확인하는지 설명한다. 실습에 필요한 OS·도구·
API 조건과 실제 코드의 제약은 해당 구현 자리에서 설명하되 작성자의 환경 보고로 바꾸지 않는다.

## 화면과 편집 규칙

짧은 복습과 확인 문제는 각각 기본적으로 접힌 `details.lesson-disclosure`로
표시한다. 제목으로 열고 닫으며, 목차나 직접 링크로 해당 절을 선택하면 펼쳐서
이동한다. 접힘 상태와 답안·완료 기록은 분리하고 기존 차시/문제 ID를 유지한다.

공통 읽기 설정·모바일 목차·차시 검색은 `usability.js`에서 제공한다. 새로운 차시도
기존 ID와 제목 구조를 유지해 탐색·키보드 초점·코드 스크롤 기능을 함께 적용한다.
설정 저장 키는 답안 저장과 분리한다. 원고에 고정 글자 크기나 테마 색을 넣지 않는다.

출발 상태와 도달점은 “이번 차시의 학습 목표” 콜아웃에 묶는다. 선수 지식은 아래에
분리한다. 산출물을 만들었다는 사실과 개념을 완전히 이해했다는 판정을 혼동하지 않는다.
차시 이동 동작의 문구는 “N차시로 이동”으로 통일한다. 이전/다음 화살표는 방향에
맞게 유지한다. 목차의 번호·제목, 선수 지식과 풀이의 참조 표시는 이동 버튼과 구분한다.

학습 순서는 기능을 만들어 가는 의존 관계로 정한다. Part 번호를 그대로 따를 필요는 없다.
창을 먼저 보여 주더라도 게임 규칙 내부에 GL/오디오/소켓 호출을 섞지 않는다.
독립 실습을 사용할 때는 누적 프로젝트에 합치는 시점과 차이를 표시한다.

## 편집 순서와 상태

- `outline`: 세부 편성만 된 상태.
- `draft`: 설명·스니펫·문제가 작성됐지만 검토 전.
- `reviewed`: 코드 대응·개념·문제와 풀이·선행 의존성을 검토함.
- 실행 검증은 별도 필드로 기록한다. 빌드 성공, 헤드리스 검증, 실제 GUI 확인,
  플랫폼별 확인을 구분하며 하지 않은 검사를 통과했다고 쓰지 않는다.

원문 전체를 가져왔다는 표시와 강의 집필 상태를 절대로 합치지 않는다. 각 원문 절이
어느 차시에 재구성됐는지 매핑을 남기고, 빠진 설명·실패 사례·코드 라벨을 점검한다.

## 본문·곁들임 메모·링크의 역할

핵심 개념과 구현에 필요한 전제는 본문에서 설명한다. `sections[].notes`는 추가 사례,
용어 구별, 적용 범위, 선택적인 복습을 위한 기본 접힘 메모다. 넓은 화면에서는 옆에,
좁은 화면과 소스 뷰어를 연 상태에서는 본문 아래에 배치한다. 메모를 열어야만 다음
코드를 이해할 수 있다면 그 설명은 본문으로 옮긴다. 1차시도 동일한 HTML 구조를 쓴다.

`kind`, `title`, `body`를 작성하며 본문과 동일한 안전한 Markdown 변환을 사용한다.
링크는 “여기” 대신 도착할 개념·실험을 이름으로 쓴다. 공식 자료는 출처와 적용 범위를
확인하고 연결한다. 외부 링크는 새 탭, 내부 절 링크는 현재 강의에서 이동한다.
예측 질문은 코드나 상태표를 읽기 전에 생각할 구체적인 입력을 주고, 본문에서 추론을
회수한다. 확인 문제·풀이와 기존 답안 ID는 유지한다. 기존 차시에도 같은 기준을 적용한다.

## OpenCode + DeepSeek 작업 분담

반복적인 자료 추출·HTML 변환·해시/링크 검사는 로컬 스크립트로 처리한다.
DeepSeek에는 한 차시 분량의 이미 고른 재료만 보내 절 분류·용어 목록·문제 초안을
요청한다. 원문 전체를 매번 보내거나 전체 저장소를 탐색하게 하지 않는다.
단순 UI·기능 구현도 사용자의 요청에 따라 OpenCode·DeepSeek에 선택한 코드와
구체적인 구현 범위를 전달해 맡긴다. 반환된 구현은 주 작업자가 검수·적용·검증한다.

생성물은 초안이다. 학습 순서, 새 CS 설명, 스니펫의 컴파일 가능성, 원문·소스와의
차이, 정답의 타당성은 주 집필자가 검토한다. 모델 결과를 강의 본문에 자동 반영하지 않는다.
API 키는 HTML·소스 저장소·프롬프트·대화에 포함하지 않는다.

## 현재 상태

작성된 차시는 학습 지도에서 확인하며, VeLog 원문과 관련 소스는 참고 패널에서 읽는다.
전체 강의의 재집필은 진행 중이다. 세부 편성안은 `course-plan.json`에 기록한다.
외부 모델 작업은 승인된 자료 범위 안에서 실행하고, 전송 재료·응답은 `out/learning-jobs/`에
별도로 보관한다. 원문 통합만으로 전체 강의 작성 완료를 주장하지 않는다.

## 객관식 문제의 계약 (2026-09-21 변경)

사용자가 기록 이동 기능을 삭제하고 “선택 → 확인 → 즉시 정답·해설”로 변경하도록
요청했다. 다음 차시에서는 정답·해설 목록 대신 짧은 복습으로 이어 간다. 이전 계획의
해설 지연·기록 파일 이동보다 이 요청을 우선한다.

각 문제는 기존 ID, options의 a~d 네 ID, correctOptionId 하나, 검토한 explanation을
갖는다. 오답은 배운 개념의 구체적인 혼동을 반영하고, 조건이 빠져 복수 정답이 되거나
정답만 유난히 자세해서 고를 수 있는 문제를 피한다. 공개된 선택지 ID의 의미와 순서를
임의로 바꾸지 않는다. 바꿔야 하면 저장된 선택의 이관 또는 초기화 범위를 설계한다.

정오 결과는 색만으로 표현하지 않는다. 확인하지 않은 선택에는 해설을 노출하지 않으며
미선택 확인은 선택 안내만 한다. 선택·확인 상태는 브라우저에 보존한다. 완료 체크는
정답 개수와 연동하지 않는다. 기존 서술 답안은 answers에 보존하고 choices 및
confirmedChoices와 분리한다. 문제 본문·보기·사용자 답안을 innerHTML로 넣지 않는다.

완성 파일은 `codes[].collapsed: true`로 기본 접힘을 지정할 수 있다. 필요한 부분
스니펫은 본문에 남기고, 이미 설명한 전체 파일은 선택적으로 펼쳐 비교하게 한다.
이 옵션은 file 참조 코드에만 적용하며 80줄 초과 파일의 자동 접힘 규칙은 유지한다.

포인터 타입처럼 별표가 있는 코드 식별자는 본문·메모에서도 인라인 코드로 감싼다.
Markdown 강조로 별표가 사라지지 않는지 실제 화면에서 확인한다. 문자 API의 길이는
바이트/코드 단위/화면 글자 수 중 무엇인지 밝힌다.


코드 블록은 sections[].codes 배열에 객체로 기록한다. 각 객체에는 label과language,
그리고 file 또는 text 중 하나만 둔다. 코드 레퍼런스 객체는 reference에 둔다.
생성기는 이 형식을 검사해 잘못된 객체가 코드 목록으로 출력되는 것을 차단한다.

원고의 `practice`에는 비어 있지 않은 `steps`·`failureChecks` 문자열 배열과 `expected` 문자열을 둔다. 생성기가 이를 검사한다. 실습 데이터가 없으면 화면 렌더링이 중단될 수 있으므로 생략하지 않는다.

## 집중 교정과 차시별 렌더링 (2026-09-23)

- CS 깊이와 현재 디자인을 유지한다. 검수 의견만으로 순서를 바꾸거나 예고를 추가하지 않는다.
- 실제 학습 맥락과 관계없는 반박·검수 잔재는 삭제한다. 학습자가 할 법한 오해의 보충 설명은
  sections[].notes로 옮긴다. 코드를 이해하는 데 필수인 전제·실패 조건은 본문에 남긴다.
- 같은 정의나 한정 조건이 인접 본문·메모에 반복되면 한 곳에 합친다. 다른 맥락에서 필요한
  실습 조건까지 일괄 삭제하지 않는다. 부정 표현의 개수만으로 편집하지 않는다.
- course.js는 현재 차시만 생성한다. 강의 목록·제목·앵커·문제 인덱스는 메타데이터로 조회한다.
  동적 차시의 답안·확인·완료 상태는 app.js가 복원하고 이벤트는 위임한다.
- 사용자 요청에 따라 이후 필수 검수는 설명·코드의 정확성과 자동 검사다. 화면 조작이나
  스크린샷 검수를 완료 조건으로 강제하지 않는다. 수행한 검사의 범위만 기록한다.

후속 집필에서 주 작업자가 선별한 C++ 학습 코드·관련 문서 발췌도 DeepSeek에 전송하도록
2026-09-23 사용자가 명시적으로 승인했다. 키·계정 정보·설정·저장소 전체는 전송하지 않는다.

## 한국어 강조 문법 (2026-09-23)

강의와 참고 원문은 `scripts/learning_markdown.py`의 공통 변환기를 사용한다.
CommonMark에 한국어 인접 문장부호의 별표 강조 규칙을 추가해 `**용어(설명)**은`,
`**`ptr`**를`처럼 조사와 붙은 표현도 strong/em으로 변환한다. 밑줄 규칙은 그대로다.
코드·백슬래시 이스케이프·링크 안전성은 Markdown 파서가 처리하며, 렌더된 HTML에
정규식으로 별표를 덧씌우거나 눈에 보이지 않는 구분 문자를 삽입하지 않는다.
`python3 scripts/check_learning_markdown.py`로 강조·중첩·리터럴·HTML 안전성을 검사한다.

## 큰 단원 완료와 커밋 (2026-10-03)

사용자의 별도 변경은 덮어쓰지 않고 이번 작업의 포함 범위를 구분한다. 푸시·공개 Pages 갱신은

## 바뀔 수 있는 수치와 설명의 기준 (2026-10-03)

강의·주제·콘텐츠 개수, 정점 속성 수, 풀·큐 용량, 지급량·시간 제한처럼 바뀔 수 있는
값을 고정된 아키텍처나 안내 문구로 설명하지 않는다. 해당 값의 출처인 카탈로그,
배열, 설정, 정책 상수와 계산식을 설명한다. 화면에서 현재 개수가 필요하면 데이터에서
계산한다. 현재 소스의 구체적인 값은 코드 레퍼런스에서 확인하도록 한다.

수치 계산이 필요한 실습은 “이 체크포인트의 예제 조건”을 먼저 밝히고 계산 과정과
단위를 설명한다. 실습 수치를 실제 게임 전체의 영구 계약으로 확대하지 않는다.
고정된 체크포인트의 코드·검증 결과, 차시 식별자, 버전이 명시된 프로토콜의 wire 규약,
과거 검수 기록과 승인된 공개 범위는 그 의미를 보존한다. 수치만 일괄 삭제하거나
실제 게임의 상수·동작을 문구 수정에 맞추어 변경하지 않는다.

큰 단원 마감 시에는 인자 없이 전체 차시 순회를 실행한다. 객관식·Markdown·정적
배포·원문 발췌·변경 코드와 누적 실습의 정확성 검사는 각 범위에 맞춰 별도로 유지한다.
