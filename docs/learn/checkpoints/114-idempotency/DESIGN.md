# 멱등 정산의 계약

- 새 스키마 이관 없음. v3/policy0·1과 요청 MatchRecord를 유지한다.
- put의 BEGIN 안에서 전체 입력과 키를 비교하고 최초 SavedAwards까지 값으로 반환한다.
- 새 요청은 커밋한 지급량, 기존 요청은 저장된 두 지급 내역을 반환한다. 현재 잔액을 넣지 않는다.
- 기존 경기인데 지급 내역이 없거나 조합/정책이 잘못되면 storage_error. 추측해 재지급하지 않는다.
- v1 네 필드와 v2 일곱 필드를 별도 경로로 제공한다. 같은 저장/검증 함수를 사용한다.
- settlement_wire는 양수uint64정체성을 보존하며 제한된 지급/정책만 검사 후uint32로 변환한다.
- 파싱 성공 뒤 호출자가 키/참가자 대응을 확인한다. HTTP 실패는 미확인,409는충돌이다.
- JSON 공백/키순서가 아닌 해석된 정수 필드를 비교한다. 다른키는 같은본문이어도 새작업이다.
- 키/입력/결과 보존 범위 안의 멱등성이며 인증/경기판정/재시도성공보장은 별개다.
- 저장된 모든 키를 유지한다. 만료/삭제/백업되돌림 정책을 추가하면 보장기간을 다시 정한다.
