# 사건의 보관과 소비

규칙/FrameRunner/Game/Application은 수정하지 않는다. 프레임 결과는 틱별 값이며
투영은 메인 스레드에서 수행한다. stopped/invalid 관찰은 무시하고, 유효 틱마다
kick>=0, hard_drop_distance>=0, cleared>0, inserted>0을 순서대로 요청으로 바꾼다.
고정 배열 용량은 max_ticks*4. take는 반환 전에 커서를 진행시킨다.
이동은 소비 위치를 보존하고 원본을 비운다. 새 투영까지 막는 전역 중복 제거는 아니다.

Player의 PCM 소유 배열과 Mixer의 보이스는 같은 슬롯 번호로 연결한다.
replace/unload는 해당 보이스만 끊고 retired를 잠금 밖에서 해제한다.
stop은 전역 pause와 stop_all이며, close는 콜백 종료 후 모든 PCM을 해제한다.
호출 제어는 메인에서 직렬화한다. 콜백 주소 안정성 때문에 Player/Session은 이동하지 않는다.

네 음원은 44100Hz/stereo/4410frames, 절댓값<=2000의 삼각파에 선형 포락선을 적용한다.
각 종류별 한 슬롯을 재시작하므로 같은 종류의 중첩 재생이나 시각 예약은 제공하지 않는다.
세 종류·여러 틱의 모든 요청을 소비했더라도 모두 끝까지 들린다는 보장은 없다.

Session 준비 중 할당/장치 실패는 부분 자원을 정리한다. 실패 후에도 규칙은 유지한다.
소리 소비는 되돌릴 수 없는 표현 시도이며 시뮬레이션 상태 해시에 포함되지 않는다.
