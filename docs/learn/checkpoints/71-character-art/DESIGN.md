# 71 · 콘텐츠 식별과 표현 자원

## 추가 이유

이름·작은 아이콘·큰 그림을 조건문마다 따로 선택하면 순서나 경로를 바꿀 때 불일치한다.
하나의 캐릭터 표를 ID로 조회하고 역할별 자원 준비와 화면 배치를 분리한다.

## 상태와 소유권

Preferences는 알려진 캐릭터 ID의 view를 보관한다. 입력 버퍼 대신 표의 정적 리터럴을
참조한다. 인덱스는 순서에 따라 파생하며 기본 ID가 표에 있음을 static_assert로 강제한다.
카탈로그는 게임 규칙 상태와 독립적이며 Round는 캐릭터 ID/이미지 핸들을 읽지 않는다.

ArtSet은 ImageStore의 핸들을 빌린다. 초기화의 지역 경로 캐시는 성공과 실패(0)를
정확한 경로 문자열 단위로 기억한다. 역할마다 fallback 플래그를 갖는다. candidate를
완성한 뒤 ready를 켜지만 외부 자원 롤백이나 멀티스레드 원자적 게시는 제공하지 않는다.
ImageStore와 GL 컨텍스트가 사용보다 오래 살아야 하며 사용 중 unload/clear하면 안 된다.

## 배치와 통합

contain은 양수 원본·상자를 받고 int64 교차 곱으로 제한 변을 정한다. 한 변을 채우고
다른 변을 내림한다. 남은 공간의 절반을 정수 나눗셈으로 배치해 여백 차이는 0 또는 1이다.
정수 양자화로 정확한 종횡비는 보장하지 않는다. 얇은 변이 0이면 생략한다.
좌표+크기는 정수 범위 안이어야 한다. main은 fixed icon frame과 메뉴 portrait box를 전달한다.

이름 목록과 선택 개수는 표에서 파생한다. 이름은 현재 디코더의 16 Unicode 스칼라 한계,
글꼴 지원·선택기 폭을 따라야 한다. 새로운 경로는 CMake 실행 자산 복사도 추가한다.
표 수정은 재빌드, 이미지 교체는 실행 자산 갱신·재시작이 필요하다.

## 현재 게임과 비교

루트 main은 설정/상대 콘텐츠에서 경로를 얻고 opponentImage에서 처음 요청한 파일을
캐시한다. 학습은 작은 정적 표를 시작 시 전부 준비한다. 루트 presentation은 같은
image_fit 순수 계산을 공유한다. 루트 avatar의 범위 밖 정수 연산과 비유한 시각 변환도
입력 검사·주기 나머지 계산으로 보강했다. Part15의 현재 발췌와 설명을 갱신했다.
루트 SDL의 window/drawable 1:1 전제는 이 작업으로 확장되지 않는다.

## 검증

실패 8조합·경로 호출 수·임시 문자열 선택·ready 공개·589824 배치 조합을 검사한다.
표 순서를 바꾼 별도 빌드에서 같은 rook ID가 올바른 이름/그림을 찾고 인덱스만 바뀌는지,
중복 ID가 컴파일 단계에서 거절되는지 확인한다. 실제 GL에서는 PNG 로딩·역할별 폴백과
가로/세로/아주 얇은 이미지의 픽셀 결과를 비교한다. 테스트 컨텍스트는 offscreen 단일
버퍼이며 실제 앱의 이중 버퍼 요구는 유지한다. 네이티브 다른 OS/수동 GUI는 별도 검증이다.
