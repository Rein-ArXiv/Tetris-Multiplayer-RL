# 클라이언트 Release 사용 안내

GitHub Release의 네이티브 클라이언트는 소스 체크아웃 없이 실행할 수 있도록 실행파일과
게임 리소스를 묶은 개발 프리뷰다. 학습 사이트 ZIP은 게임 실행파일과 별도로 제공한다.

## 파일 선택과 실행

| 파일 | 대상 | 실행 방법 |
| --- | --- | --- |
| `tetris-win-x64.zip` | Windows x64 | 전체 압축을 풀고 `tetris.exe` 실행 |
| `tetris-linux-x64.tar.gz` | Linux x64 | 전체 압축을 풀고 번들 폴더에서 `./tetris` 실행 |
| `tetris-macos-arm64.tar.gz` | Apple Silicon Mac | 전체 압축을 풀고 `Tetris.app` 실행 |
| `tetris-macos-x64.tar.gz` | Intel Mac | 전체 압축을 풀고 `Tetris.app` 실행 |
| `tetris-learning-site.zip` | 웹 브라우저 | 전체 압축을 풀고 `index.html` 열기 |

실제 제공된 파일과 대상 OS 버전은 해당 Release의 설명·빌드 정보에서 확인한다.
실행파일만 따로 옮기면 폰트·음원·아이콘을 찾지 못한다. 클라이언트에는 OpenGL 3.3을
지원하는 그래픽 환경이 필요하며, 터미널 전용 서버에서는 GUI 클라이언트가 실행되지 않는다.
Linux 번들에는 일부 공유 라이브러리를 포함하지만 libc·그래픽 드라이버·시스템 오디오까지
포함하지 않는다. `ldd ./tetris`에서 `not found`로 표시되는 시스템 패키지는 설치해야 한다.

macOS 파일은 아키텍처별로 제공한다. 로컬 ad-hoc 서명은 패키징 후 코드 무결성을 위한
서명이며 Apple Developer ID 서명이나 공증이 아니다. 다운로드한 앱은 macOS 보안 정책에
따른 확인이 필요할 수 있다. 시스템 전체 보안 설정을 끄도록 안내하지 않는다.

## 플레이와 서버 연결

기본 배포에는 공개 서버 주소를 내장하지 않는다. 로컬 플레이와 내장 휴리스틱 봇을 사용할
수 있다. 온라인 대전·익명 계정·공용 BP에는 호환되는 별도 서버가 필요하다. 로그인 없는
로컬 플레이와 서버에 저장되는 계정 진행을 혼동하지 않는다.

이 프리뷰는 ONNX Runtime과 학습 모델을 포함하지 않는다. Colab 학습 결과를 넣는 방법은
[봇 학습·콘텐츠 안내](bots-and-colab.md)를 따른다. 설정 가능한 서버 주소와
로컬 기본값은 [프로젝트 README](../README.md)의 서버 연결 절을 참고한다.

## 빌드와 갱신

`.github/workflows/release-build.yml`은 main에서 수동 실행하며, 동일 커밋의 OS별 패키지와
학습 ZIP을 Actions 산출물로 만든다. 워크플로는 Release를 자동 발행하지 않는다.
담당자는 성공한 산출물·실제 의존성 검사·커밋 SHA를 확인한 뒤 새 태그의 Release로 공개한다.
기존 공개 태그를 새 코드로 이동하거나 서로 다른 커밋의 실행파일을 한 버전으로 섞지 않는다.

기본 엔드포인트와 BOT/debug 옵션은 릴리스 스크립트가 명시적으로 설정한다. 계정 파일,
운영 DB, TLS 개인키, 로컬 설정은 패키징 입력에 포함하지 않는다. GitHub의 깨끗한 체크아웃에서
빌드하며 실행기 OS와 아키텍처를 빌드 정보에 기록한다. 빌드·의존성 검사와 실제 사용자 환경의
창·입력·오디오 확인은 서로 다른 검증이며, Release 설명에는 수행한 범위만 쓴다.
