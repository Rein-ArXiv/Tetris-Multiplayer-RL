# 경기 사실과 저장 확인의 경계

- MatchRecord는 신뢰된 완료 시뮬레이션에서 호출자가 만든 값이다. 기본 필드 검사는 승패 검증이 아니다.
- prepare는 empty에서 한 번 복사한다. 키·내용은 const 접근만 가능하고 다시 준비할 수 없다.
- 한 소유자가 모든 호출을 직렬화한다. 콜백은 재진입하거나 요청 참조를 비동기로 보관하지 않는다.
- submit 한 번은 콜백을 최대 한 번 호출한다. 횟수 상한은 경과 시간 제한이 아니다.
- 호출 전에 시도 수를 늘리고 unconfirmed로 둔다. 영수증의 키·양수 행·순서 있는 참가자가 맞아야 confirmed다.
- 횟수 소진은 저장 여부를 확정하지 않는다. ready/unconfirmed 상태를 유지한다.
- 객체는 복사/이동하지 않는다. 객체 수명은 동기 호출과 request/receipt 참조 사용보다 길어야 한다.
- ReceiptService는 한 행의 메모리 대역이다. 첫 반영 후 응답 미확인을 만들고 동일 요청에 원래 영수증을 준다.
- 다른 키를 포함한 다른 내용은 대역의 확인 대상이 아니다. 일반 다중 행 저장소로 사용하지 않는다.
- 프로세스 재시작 뒤 재전송은 별도 지속 저장 대기열이 필요하다. 서비스 중복 판정의 보존 수명도 계약이다.
- 실제 service 응답은 학습 Receipt와 다르며 JSON 어댑터의 구조·범위 검사를 거쳐야 한다.
- 107 누적 파일은 README/DESIGN/CMake 외 바꾸지 않는다. TCP 종료 결과 실습은 기존 규칙을 재사용한다.
