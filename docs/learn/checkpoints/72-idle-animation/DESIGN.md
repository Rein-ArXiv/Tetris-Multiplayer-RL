# 72 · 표현 시계와 조회

## 추가 이유

규칙의 고정 스텝은 대기 메뉴에서 흐르지 않는다. 화면 효과를 그 시계에 붙이거나
매번 그릴 때 난수를 새로 뽑으면 목적에 맞는 정지/재개와 부드러운 파형을 얻기 어렵다.
효과의 시간 상태를 UI 세션이 소유하고 그리기는 현재 상태를 조회한다.

## 구현 경계

Clock은 초 단위 경과량을 받고 [0,4)의 효과 시간을 보관한다. advance는 명령,
sample은 조회다. 양수 유한 입력을 먼저 검사하고 active=false면 no-op 성공이다.
큰 dt는 0.1로 자르므로 현실 시간 동기화나 모든 경과 시간 보존을 보장하지 않는다.
각 단계가 같은 호출의 원자적인 OS 시간 관찰을 뜻하는 것도 아니다.

Animation 생성자는 로컬 RNG 두 값을 53비트 정수로 줄여 2^53으로 나눈다.
위상 오프셋은 [0,1)이다. 고정 기본 시드이며 랜덤 시드 생성 기능은 없다.
게임의 조각/가비지/고정 효과 엔진과 별개 상태다. 같은 seed여도 가변 엔진을 공유하면
소비 순서가 결과에 영향을 준다. 표본화마다 난수를 소비하지 않고 매끄러운 sin을 읽는다.

활성 조건은 menu/decorations/layout이다. 시계 정지와 정적 표시를 구별한다.
sample(false)는 border=1/portrait=1/angle=30을 반환하지만 저장한 위상은 바꾸지 않는다.
꺼질 때 정적인 모습으로, 켜질 때 보관한 위상으로 전환된다. 화면 전환·최소화 동안에도
시계 객체 자체는 유지된다. 설정의 체크박스는 기존 ‘장식 표시’를 사용한다.

알파는 테두리/일러스트에만 적용하며 라벨·사각형·hitbox를 변형하지 않는다.
장식은 비대화형이다. ImageStore는 텍스처를 다시 업로드하지 않고 tint 알파로 표시한다.
동일한 double 연산 경로의 반복 조회와 플랫폼을 바꾼 sin/래스터 결과의 동일성은 구별한다.

## 현재 게임과 비교

루트 아바타는 전달받은 절대적 플랫폼 시간에서 파형을 계산해 재개 시 현재 위상으로 간다.
상점 shopSpin은 활성 dt를 누적해 비활성 때 각도를 보관한다. 루트 dt의 상한이 유지되는
조건에서 회전각의 한 번 빼기 wrap은 유효하다. 이 검토에서는 새 루트 코드 오류를 찾지
않았으며 Part15에 서로 다른 시간·재개 계약과 공유 난수의 실제 위험을 보강했다.

## 검증

음수/NaN/무한 dt와 pause/clamp/wrap, 정확히 표현되는 시간 분할, 장기 주기 반복,
사분주기의 독립 alpha 기대값·회전각, 반복 조회와 seed별 오프셋을 검사한다.
실제 규칙을 진행한 두 Game에 효과 호출 수/설정만 다르게 끼워 넣고 매 프레임 상태 해시·
규칙 위상·기존 고정 효과 난수 상태를 비교한다. 상태 변화와 lock이 실제 발생함도 검사한다.
GL에서는 알파/고정 사각형의 픽셀 색을 허용오차 안에서 비교하고 회전 제출 오류를 확인한다.
이는 native GUI나 다른 GPU/OS에서의 동일 픽셀 검증이 아니다.
