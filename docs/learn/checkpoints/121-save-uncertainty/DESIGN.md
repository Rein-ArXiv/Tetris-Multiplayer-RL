# 작업의 정체성과 저장 지식

- 120 누적 기능 유지. 계정의 제한 파일 읽기를 local_document로 추출하고 같은 계약을 검사한다.
- 한 폴더는 한 불변 경기 요청과 origin을 소유한다. 협력 잠금은 Store 수명 동안 유지한다.
- 전송 전에 요청 저장 성공을 확인한다. 새 세션은 보이는 파일도 다시 확정한 뒤 보낸다.
- pending은 미확인, stopped는 자동 중단, confirmed는 대응하는 유효 영수증의 관찰이다.
- 서버의 동일 key/내용 중복 처리 계약과 최초 영수증에 의존한다. 로컬/원격 원자 트랜잭션은 없다.
- confirmed와local_saved=false는 유효하다. 메모리의 영수증을 지우지 않고 파일만 재시도한다.
- 요청/참가자/내용/origin을 바꾸거나 confirmed를pending으로 되돌리지 않는다.
- stopped/confirmed 파일을 재개하면 HTTP를 보내지 않는다. 상태 저장 실패 때 종료하면 그 사실이 디스크에 없을 수 있다.
- 한 manual deliver는 3회/5000ms 진입 예산. 새 resume은 새 예산이며 전체 수명의 전송 상한은 아니다.
- 완료 영수증은 유지한다. prepare는 기존 작업을 덮지 않는다. 대량 큐 정리·보관 정책은 없다.
- 신뢰하는 로컬 시뮬레이션 결과/loopback 학습 API다. 임의 파일 작성 권한은 서버의 보상 권한이 아니다.
- 복구 범위는 요청 준비 성공 이후다. 준비 전 게임 상태를 복구하거나 악성 동일 사용자·원격FS를 방어하지 않는다.
- 실제 게임은 ResultStatus Applied/Draw일 때만 보고된 RP를 캐시에 반영한다.
