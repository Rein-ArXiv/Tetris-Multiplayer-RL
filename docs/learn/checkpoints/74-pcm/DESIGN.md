# PCM 데이터의 계약

- signed16, host byte order, interleaved mono/stereo. rate 8000~192000은 앱 정책.
- 레이트는 채널당 초당 샘플 수이며 PCM 프레임/초와 같다.
- layout_s16은 할당 없이 전체 프레임 수를 바이트 예산과 대조한다. 나눗셈 검사 뒤 캐스트/곱셈.
- Pcm16::make는 이미 전달받은 vector를 검증한다. 16MiB 한도는 보관 승인 정책이며 호출 전 할당을 막지 않는다. 빈 버퍼·반프레임·미지원포맷을 거절한다.
- 개수는 저장 배열에서 계산한다. 별도 캐시를 두지 않아 복사/이동 뒤 오래된 개수가 남지 않는다. 이동한 원본은 C++ vector의 유효하지만 미지정 상태이며 조회는 실제 잔여 배열 기준이다.
- samples()의 참조는 소유자 수명과 이동/대입 경계를 넘겨 보관하지 않는다. at은 프레임·채널 각각을 확인한다.
- make_reference_tone은 주기100프레임 정수 삼각파를 L/R에 복제한다. 44100Hz에서는 기본주파수441Hz이며 양쪽이 같은 신호다. 실제 공간 차이를 합성하지 않는다.
- Pcm16 데이터 준비/할당은 도구에서 수행한다. main·설정 파일·규칙 입력·RNG·GPU에 의존하지 않는다. 학습 오디오 장치 API는 아직 없다.
- 루트 공통 layout 헤더는 같은 계산이다. 루트는 디코더 출력과 API 제출 한도로 사용한다. 이 단계의 제한이 파일 읽기/디코더 내부 할당 전체의 보안 경계를 완성했다고 해석하지 않는다.

대입은 값 매개변수 복사를 먼저 완성하고 예외 없는 swap으로 형식과 배열을 함께 교체한다. 복사 할당 실패가 형식만 바꾸는 부분 대입을 피한다.
