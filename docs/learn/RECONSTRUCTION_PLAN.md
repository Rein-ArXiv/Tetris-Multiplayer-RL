# 전체 강의 재구성 계획

## 목표와 범위

Part 0~18을 재료로 빈 디렉터리에서 게임·렌더러·통신·서버·봇을 만들어 간다.
원문 참고 패널은 보존하지만, 원문을 불러왔다는 사실은 집필 완료를 뜻하지 않는다.
학습자는 HTML에서 강의·객관식 문제와 즉시 해설·짧은 복습·현재 소스를 함께 읽는다.

구현 주제의 의존 관계를 따라 영역과 차시를 편성한다. 한 차시에 새로운 전제가 너무 많으면
나누며, 주제와 차시의 수는 집필 과정에서 조정한다. 마지막 실습 뒤에는 전체 구현을 복습하고 다음 설계로 잇는 차시를 둔다. 순서는 `course-plan.json`이
관리하며, 기본 선행 조건은 직전 차시다. 다른 경로로 진입할 수 있는 단원도 처음
소개되는 계약을 생략하지 않는다.

## 구현 순서와 도달점

| 영역 | 누적 결과 | 다음 영역이 사용할 계약 |
| --- | --- | --- |
| 프로그램과 창 | 실행·종료·입력을 처리하는 플랫폼 계층 | 플랫폼이 OS 자원을 소유 |
| GPU 첫 도형 | 화면 좌표로 사각형을 제출하는 렌더러 | 규칙에서 GL을 호출하지 않음 |
| 보드와 규칙 | 이동·낙하·고정·회전·공격이 있는 한 판 | 상태 전이는 입출력 없이 수행 |
| 시간과 재현성 | 고정 스텝·기록·재현·검증 | 동일 초기 상태와 입력 순서 |
| 이미지·글자·UI | 아이콘·글자·설정·표현 애니메이션 | 표현 시계·자원은 규칙과 분리 |
| 소리 | 이벤트에 반응하는 재생 계층 | 장치 실패가 규칙을 바꾸지 않음 |
| 네트워크 | 입력과 해시를 교환하는 두 클라이언트 | 바이트 경계·순서·수량 검증 |
| 릴레이 | 매칭·방·수락·종료 | 연결 수명과 경기 수명의 구분 |
| 계정·보상 | 익명 계정·아이콘·거래·결과 저장 | 서버 판정과 원자적 저장 |
| 서버 동시성 | 스레드와 Reactor 구현 비교 | 동일 경기 계약, 다른 I/O 소유권 |
| 공개 서비스 | 전송 보호·토큰·권위 판정 | 신뢰 경계와 남은 어뷰징 명시 |
| 봇 | Python 환경·학습·추론·캐릭터 대전 | 모델·입력 속도·보상 검증 분리 |
| 배포·유지보수 | Linux 운영·Windows 이전 계획 | 빌드·실행·권한·백업을 구분 |

보상과 계정 단원에서 보안이 완성됐다고 가정하지 않는다. 뒤에서 보강할 경계를
명시한다. Colab·네이티브 GUI·타 OS 검증은 실제 수행 여부를 따로 적는다.

## 한 차시를 완성하는 단위

1. 시작 상태·추가할 기능·학습 후 설명할 수 있어야 할 질문을 결정한다.
2. 원문의 관련 절과 실제 소스의 필요한 심볼만 고른다. 파일 이름과 내용 식별값을
   기록한다. CS 정의 → 수치/상태 예 → 구현 → 실패 → 대안의 설명을 집필한다.
3. 기준 스니펫은 독립 버전으로 보관한다. 완성 파일과 부분 발췌를 명확히 나누고,
   선행 실습에서 무엇을 교체·추가하는지 적는다.
4. 현재 소스는 파일·검색 문자열로 연결한다. 유지할 핵심, 달라질 세부, 아직
   도입하지 않은 부분을 따로 설명한다.
5. 4지선다 3~5문제를 만들고 정답·오해를 검토한다. 확인 시 그 자리에서 해설하고, 다음 차시에는 짧은 복습으로 연결한다.
6. 실행 가능한 체크포인트는 빌드·실행한다. 자동 검사는 링크·구조·누락을 확인하며
   개념의 정확성이나 GUI 정상 작동을 대신 증명하지 않는다.
7. 검토된 본문만 학습 화면에 연결한다. 초안은 공개 강의 목록에 넣지 않는다.

## 원문 누락 추적

`coverage.json`은 Part 0~18의 실제 Markdown 제목 토큰을 기준으로 모든 2단계 절을
목록화한다. 하위 절과 코드·실패 사례도 상위 절 범위에 포함된다. 원문의 소개·요약·
구현 계약도 목록에서 지우지 않는다. 각 항목에는 후보 단원과 실제 집필된 차시를
별도로 기록한다. 후보 단원 배정은 해당 내용이 강의에 포함됐다는 뜻이 아니다.
파일 변경 시 내용 해시를 비교하고, 기존 검토 상태를 조용히 재사용하지 않는다.

`coverage-routing.json`은 원문 제목·하위 제목으로 고른 집필 후보다. DeepSeek의
분류 초안을 보존하되, 시범 차시와 확인한 경계는 편집했다. 본문 전체의 대응을
검토한 것은 아니므로 HTML에서도 “제목 기반 집필 후보 · 본문 대조 전”으로 표시한다.
이 분류의 누락·중복 ID와 차시 존재 여부를 로컬 검사한다.

## 외부 모델 사용

2026-09-21 사용자가 `library-manifest.json`에 기록된 문서 28개·소스 154개 중
필요한 구간의 DeepSeek 전송을 승인했다. 첫 작업의 집필 기준 파일도 승인 범위다.
키·계정 파일·DB·로컬 설정은 보내지 않는다. OpenCode의 저장소 탐색이나 도구
실행을 시키지 않고, 작업별 첨부 자료만 제공한다.

단순 추출·해시·HTML 조립·검사는 로컬에서 수행한다. DeepSeek는 선택된 재료의
설명·문제 초안을 반환한다. 전송 자료와 응답은 무시되는 `out/learning-jobs/`에
보관하고, 성공 결과를 재사용한다. 오류·불완전 JSON·본문 누락은 집필 성공으로
집계하지 않는다. 주 집필자가 편집·검토한 결과만 버전 관리 대상 본문에 넣는다.

## 첫 실행 묶음

- 1차시 기존 본문과 저장된 답안을 보존한다.
- 2차시 창의 생성·핸들·실패 경로·종료와 1차시 해설을 추가한다.
- 3차시 이벤트 큐·블로킹·폴링·렌더 루프의 이유와 2차시 해설을 추가한다.
- 다차시 탐색·문제 저장·직전 해설·현재 소스 비교를 실제 화면에서 확인한다.
- 이 형식을 통과한 뒤 후속 차시를 같은 품질 기준으로 늘린다. 전체 강의 완료는
  모든 차시 검토와 원문 내용 대응 검토가 끝났을 때만 표시한다.
